# Azy Programming Language

**Azy** — это разрабатываемый компилируемый язык программирования общего назначения, создаваемый с нуля на C++.

---

## 📌 Текущий прогресс разработки

| Этап | Статус |
|---|---|
| **Лексический анализатор (лексер)** | ✅ завершён |
| **Синтаксический анализатор (парсер)** | 🚧 в активной разработке |
| **Семантический анализ** | ⏳ запланирован |
| **Интерпретатор AST** | ⏳ запланирован |

Лексер полностью готов и стабилен: преобразует исходный код в последовательность токенов. Парсер использует метод рекурсивного спуска, строит абстрактное синтаксическое дерево (AST) и **продолжает развиваться** — добавляются новые конструкции, расширяется грамматика, дорабатывается обработка ошибок.

**Важно:** синтаксис языка ещё не заморожен. Грамматика может меняться по мере развития парсера.

---

### ✅ Возможности лексера (готов)

* **Типизация токенов (`TokenType`):** идентификаторы (`Identifier`), целые числа (`Int`), числа с плавающей точкой (`Float`), строки (`String`), операторы (`Operator`), неизвестные символы (`Unknown`).
* **Продвинутая обработка чисел:** корректный разбор целых чисел, чисел с плавающей точкой (`3.14`), чисел, начинающихся с точки (`.5`), а также безопасное распознавание одиночной точки как оператора.
* **Строковые литералы:** выделение текста в кавычках (`"..."`).
* **Комментарии — все три вида:**
  * однострочные через решётку — `# комментарий`
  * однострочные через двойной слэш — `// комментарий`
  * многострочные — `/* ... */`
* **Полный набор операторов:**
  * арифметические: `+`, `-`, `*`, `/`
  * сравнения: `==`, `!=`, `<`, `>`, `<=`, `>=`
  * логические: `&&`, `||`, `!`
  * инкремент/декремент: `++`, `--`
  * составное присваивание: `+=`, `-=`, `*=`, `/=`
* **Трекинг позиций:** точное определение номера строки и колонки для отладки.

---

### 🚧 Возможности парсера (в разработке)

Парсер построен методом **рекурсивного спуска с предпросмотром** (`peek`, `peekNext`, `check`, `checkNext`). На выходе — AST на `std::unique_ptr`, с иерархией узлов `ASTNode` → `ExpressionNode` / statement-узлы.

**Уже работает:**

* **Управляющие конструкции:**
  * условные ветвления (`if / else`, включая цепочки `else if` и вложенные `if`);
  * цикл с предусловием `while (...) { ... }`;
  * цикл с постусловием `do { ... } while (...);`;
  * **`for` в трёх формах:**
    * сокращённая: `for (i == 5) { ... }` — по умолчанию `i = 0`, шаг `i++`;
    * полная (C-style): `for (i = 0; i == 10; i++) { ... }`;
    * foreach: `for (x in text) { ... }` — перебор по строке;
  * **управление циклом:** `break;`, `continue;`;
  * изолированные блоки кода `{ ... }`.

* **Операторы и выражения:**
  * присваивание: `=`, `+=`, `-=`, `*=`, `/=`;
  * постфиксные инкременты/декременты: `i++`, `i--`;
  * унарные операторы: `!`, `not`, `-`;
  * вывод: `print(...)` и `print.ln(...)`.

* **Литералы:**
  * `int` — `42`;
  * `float` — `3.14`, `.5`;
  * `string` — `"Hello, Azy!"`;
  * `bool` — `true`, `false`.

* **Иерархия приоритетов выражений (снизу вверх):**
  1. логическое ИЛИ (`||`);
  2. логическое И (`&&`);
  3. операторы равенства (`==`, `!=`);
  4. операторы сравнения (`<`, `>`, `<=`, `>=`);
  5. сложение и вычитание (`+`, `-`);
  6. умножение и деление (`*`, `/`);
  7. унарные операторы (`!`, `not`, `-`);
  8. базовые литералы, переменные и вложенные скобки `(...)`.

* **Обработка ошибок:**
  * понятные диагностические сообщения с указанием строки, символа и контекста сбоя;
  * защита от зацикливания в `parse()` — парсер не зависает при некорректном вводе;
  * мягкая обработка неожиданных токенов: неизвестный токен пропускается с предупреждением, разбор продолжается;
  * **печать AST** в читаемом виде — дерево выводится с отступами, каждый узел на своей строке.

**В работе / запланировано:**

| Возможность | Статус |
|---|---|
| Префиксные `++i`, `--i` | 🚧 запланировано |
| Массивы: литералы `[1, 2, 3]`, индексация `arr[i]` | ⏳ запланировано |
| Функции: `def name(a, b) { ... }`, вызовы `name(1, 2)` | ⏳ запланировано |
| Встроенные функции: `len(x)`, `range(n)` | ⏳ запланировано |
| Тернарный оператор `? :` | ⏳ запланировано |
| `switch / case` | ⏳ запланировано |
| Escape-последовательности в строках (`\n`, `\t`, `\"`) | ⏳ запланировано |
| Семантический анализ | ⏳ следующий этап |
| Интерпретатор AST | ⏳ следующий этап |

```text
AZY/
├── Application/              # Собранные бинарники и тестовые скрипты
│   ├── AZY_compiler              # Исполняемый файл компилятора (Linux ELF)

│   ├── test_break.azy            # Тест управления циклом: break / continue

│   ├── test_if.azy               # Тест условных ветвлений: if / else / else if
│   └── test_print.azy            # Тест вывода: print(...) и print.ln(...)
├── src/                      # Исходный код компилятора
│   ├── lexer.cpp                 # Реализация лексического анализатора
│   ├── lexer.h                   # Интерфейс лексера
│   ├── parser.cpp                # Реализация синтаксического анализатора
│   ├── parser.h                  # Интерфейс парсера и определения узлов AST
│   ├── Token.h                   # Определение структуры Token и перечисления TokenType
│   └── main.cpp                  # Точка входа (лексер → парсер → печать AST)

└── CMakeLists.txt            # Конфигурация сборки CMake
```

## 🛠 Сборка и запуск проекта

Для сборки проекта требуются:
- компилятор с поддержкой **C++17** (GCC 7+, Clang 5+, MSVC 2017+);
- система сборки **CMake** версии **3.10** и выше.

---

### ⚠️ Важно: пересобирайте проект локально

Готовые бинарники в папке `Application/` **не гарантируют работу на вашей системе**. Причины:

- разработчик может вести разработку на **другой ОС** (Linux / Windows / macOS);
- разные версии **компиляторов** создают несовместимые бинарники;
- разные архитектуры (**x86_64 / ARM64**) требуют разной сборки;
- бинарники **устаревают** быстрее, чем обновляется исходный код.

**Правило:** после каждого релиза, обновления из репозитория или смены ветки — **всегда пересобирайте проект заново**. Только так вы получите работоспособную версию компилятора для своей системы.

> 💡 Если в `Application/` лежит файл с расширением `.exe` — это Windows-бинарник. На Linux / macOS он не запустится, игнорируйте его.

---

### 🧹 Шаг 1. Очистка готовых сборок после клонирования

**Сразу после клонирования репозитория** удалите старые бинарники из папки `Application/`. Это обязательный шаг — иначе возможны конфликты:

- на **Linux / macOS** окажется ненужный `.exe` от Windows-сборки;
- на **Windows** останется ELF-бинарник без расширения, который система не распознает;
- запуск старого бинарника может привести к **непонятным ошибкам** вместо ожидаемой работы свежего кода.

```bash
cd Azy

# Удалить все собранные бинарники (любой ОС)
rm -f Application/AZY_compiler*
```

> 💡 На Windows вместо `rm` используйте `del`:
> ```cmd
> del Application\AZY_compiler
> del Application\AZY_compiler.exe
> ```

Тестовые файлы `test_*.azy` **удалять не нужно** — они кроссплатформенные и содержат только исходный код.

### 🧱 Шаг 2. Клонирование и компиляция

```bash
# Клонирование репозитория
git clone https://github.com/Azyholl-Lab/Azy.git
cd Azy

# Создание директории сборки
mkdir -p build
cd build

# Генерация файлов сборки и компиляция
cmake ..
cmake --build .
```

После сборки бинарник появится в `build/`. Чтобы запускать его из `Application/`, скопируйте:

```bash
cp AZY_compiler ../Application/
```

**Если проект уже собран ранее, а вы обновились — пересоберите начисто:**

```bash
cd build
rm -rf *
cmake ..
cmake --build .
cp AZY_compiler ../Application/
```

---

### ▶️ Шаг 3. Запуск анализатора

После сборки исполняемый файл можно запустить **тремя способами**.

#### 1. Анализ файла с исходным кодом

```bash
cd Application/
./AZY_compiler test_all.azy
```

На выходе:
- список распознанных токенов с типами и позициями;
- готовое дерево AST в читаемом виде;
- сообщение об окончании разбора.

#### 2. Прогон всех тестов разом

Удобно после правок в парсере — проверяет, что ничего не сломалось:

```bash
cd Application/
for f in test_*.azy; do
    echo "===== $f ====="
    ./AZY_compiler "$f" 2>&1 | grep -E "Пропущен|Ошибка|Парсер закончил"
done
```

Если по всем файлам выводится `Парсер закончил` без предупреждений — парсер работает корректно на всём наборе конструкций.

#### 3. Интерактивный ввод из консоли

Для проверки кода «на лету», без создания файла:

```bash
cd Application/
./AZY_compiler
```

После запуска вводите код прямо в терминале. Для завершения ввода используйте:

- **Linux / macOS:** `Ctrl + D`
- **Windows (cmd):** `Ctrl + Z`, затем `Enter`
- **Windows (PowerShell):** `Ctrl + Z`, затем `Enter`

### 🔄 Почему нельзя просто скачать готовый бинарник

Azy — **компилируемый** язык, а не интерпретируемый. Компилятор — это **нативная программа** под конкретную ОС и архитектуру. Бинарник, собранный на:

| Сборка на | Не запустится на |
|---|---|
| Linux x86_64 | Windows, macOS, ARM |
| Windows x64 | Linux, macOS |
| macOS ARM (M1/M2) | Linux, Windows x86 |
| GCC 9 | Система с GCC 13 (иногда — ABI-несовместимость) |

Даже в пределах одной ОС **разные версии libc / libstdc++ / MSVC runtime** могут давать ошибки линковки. Поэтому единственный надёжный способ — **собрать компилятор локально** одной командой:

```bash
cmake .. && cmake --build .
```

Сборка занимает несколько секунд — это дешевле, чем разбираться с «не запускается, что делать».
